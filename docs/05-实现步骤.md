# 05 · 实现步骤

本轮交付止于设计仓库。以下阶段是下一轮工程任务，不代表已创建对应文件或运行测试。任务优先级和依赖见 [10](10-实施任务清单.md)；所有实施都先以 [06](06-测试与验证.md) 的隔离环境完成spike，不能借用现有Profile/token试错。

## 5.1 工程约束与最小结构

采用Python3.11+，复用明确配置的Hermes venv解释器和其核心psutil依赖。使用stdlib的argparse、fcntl、socket、subprocess、selectors、json、logging和原子文件操作；YAML解析只用于目标Profile预检，复用已安装的解析器，不导入Hermes main。先不引入Web UI、后台队列、SQLite或第二个常驻daemon。

拟定未来文件如下；按实现需要可以合并小模块，不为表格机械制造抽象层：

| 文件 | 责任／接口 |
|---|---|
| `herdr-plugin.toml` | 唯一startup、限定events、gateway pane和actions |
| `bin/hermes-gateway-herdr` | 很薄的可执行launcher；只读取可信绝对runtime-python，不source config，不后台fork |
| `src/main.py` | CLI dispatcher、JSON输出、deadline；只把已验证的本插件目录加入模块查找路径 |
| `src/state.py` | schema、固定inode flock、原子写、intent/pending/fuse CAS |
| `src/identity.py` | UID、canonical paths、OS fingerprint、PID复用、进程／pane关系 |
| `src/herdr.py` | 有界只读／创建RPC，解析实际schema；无自行launch server功能 |
| `src/hermes.py` | 指定SHA的socket协议adapter、Profile预检、R1/R2、退出分类 |
| `src/controller.py` | `ensure(context)`、action→持久intent、adopt／replace协调 |
| `src/supervisor.py` | lifetime锁、child、日志、probe、退避、信号和控制socket |
| `src/profile_init.py` | 空白暂存root创建／迁入、配置操作、初始paused；无secret复制 |
| `assets/SOUL.md`、`assets/skills/herdr-control/SKILL.md` | 受审计模板、版本与hash |
| `tests/unit/`、`tests/integration/`、`tests/e2e/` | 时钟／PID故障模型、假Gateway、隔离真实场景 |
| `packaging/launchd/`、`packaging/systemd/` | 后续可选Herdr service和短ensure timer模板 |

协议类型无需通用IPC框架。最小接口结果必须有 `code/state/owner_key/generation/intent_revision`；错误返回结构化原因，禁止把完整env或平台token带回日志。

## 5.2 阶段0：最小可执行 spike（P0，先行 gate）

**目的**：验证影响所有权的事实，先不实现全部产品体验。隔离资源：独立测试Herdr session、临时插件目录、无真实凭据的测试Profile；需要真实消息时使用独立测试账户／bot。全部测试资产放项目内专用临时目录或测试环境，不改references、当前Profile和全局恢复配置。

未来新增：`spike/README.md`、`spike/herdr-plugin.toml`、最小argv launcher／受控假child、只读socket probe、`spike/results.md`。测试fake不能伪装为完整产品supervisor。

1. 用最小plugin tab启动参数回显进程，只报告四个HERDR字段、PID/SID、指纹、cwd；对照Herdr pane/process API，确认no-focus和argv空格／特殊字符边界。
2. 最小parent启动可指定退出结果的假child；观察普通pane中child/supervisor退出、75、0及SIGTERM。验证同SID、stdio排空和Herdr进程清理；不采用setsid逃离pane。
3. 无凭据隔离Profile启动真实Hermes，探测gateway.sock identify/status、验证identity字段与platform writer；cron-only必须判not-ready。精确记录所选CLI遇到损坏YAML的结果，不预设必为2。
4. 验证直接fresh create会读取来源model block的源码线索，用只有假哨兵值的source fixture测试；空白暂存root创建／原子迁入不得把哨兵值、auth、cron、skills或记忆带入。复核迁入后-p与HERMES_HOME一致。
5. 给运行中的测试pane做live handoff，记录前后Gateway PID/start、PTY/SID、pane IDs、plugin ownership API结果、startup再次触发。随后使supervisor退出，验证是否回shell和是否缺退出事件。
6. 做cold restore、debounce窗口内杀Herdr、Herdr SIGKILL/restart；查看是否存在孤儿、socket暂失、旧ID失效。不能把进程仅kill0存活写成ready。
7. 若准备支持native-managed Herdr，分别在macOS和Linux隔离环境验证native主PID/cgroup与handoff。未通过就冻结“native模式只cold restart”的支持边界。

**验收**：每条有命令、版本/SHA、脱敏输出、时间和实际/预期对比；真实pane env准确；没有同Profile双Gateway；孤儿和handoff失联有可判定分支。不能通过“sleep足够久”或全局关闭Herdr agent restore规避问题。未解决核心PTY/孤儿安全问题不进入完整实现；native handoff失败只阻断该兼容模式。

**回滚**：先验证并停测试PID/pane，禁用测试plugin，再停测试session；删除明确测试根。保留spike报告，不触碰线上token、default Profile或其他workspace。

## 5.3 阶段1：状态、身份和只读 doctor（P0）

新增main/state/identity/herdr/hermes的最小只读部分与单元测试；不接入startup自动创建。

- 实现schema1、binding、intent revision、pending/fuse、固定inode flock、原子写及fsync。
- 把parse错误、版本不支持、symlink、owner/mode错误、PID reuse、socket无响应分成明确结果；权限错误不能当“进程不存在”。
- 实现 `doctor --json`、`status --json`、`status --require-ready`。Herdr/Hermes协议采用明确字段，不解析彩色控制台输出。
- R1/R2检验回答者和platform writer身份；socket存在、旧connected状态不得误报ready。

**验收**： [06单元U01–U10](06-测试与验证.md#unit) 通过；doctor没有spawn/kill/profile mutation；不同XDG/TMPDIR仍指向同Profile锁；所有检测都有有界deadline。

**回滚**：仅移除新增测试数据和未发布代码；读操作不产生需要恢复的用户配置。

## 5.4 阶段2：pane 内 supervisor（P0）

新增supervisor、IPC白名单、日志轮转、child环境构造；先用fake Gateway验证，再用阶段0测试Profile。

- `supervise`先校验真实pane context与generation，再持lifetime lock；没有pending／匹配intent时拒绝启动。
- spawn精确argv，保留真实Herdr环境和同SID；屏蔽来源secret、native supervisor markers与Python注入。
- 处理75、1、0、2/78、负signal returncode；persist backoff/fuse；较新的intent revision优先于旧child退出结果。
- Stop和Restart分开；TERM→wait→KILL每步重验身份；实时排空child pipes；磁盘失败和pipe满不挂死主循环。

**验收**：fake child计数始终≤1；75换child不换supervisor；0落pause；2/78只启动一次就熔断；重复restart不重复发信号；kill0通过但socket无响应不得READY；信号清理和stdio见 [06](06-测试与验证.md)。

**回滚**：持久pause、等待child结束再关闭测试pane；保留intent和错误诊断。不能只卸载manifest让进程遗留。

## 5.5 阶段3：controller、layout 与恢复（P0）

实现唯一ensure入口、完整manifest、startup/events/actions。发布前保持测试plugin disabled，单独调用doctor和受控action。

- 按03的短锁预留协议创建workspace/pane，所有创建显式no-focus。
- 同generation pending去重；RPC响应丢失不盲重发；不要持mutation锁等supervisor。
- handoff只adopt own ledger；close/focus使用验证后的普通pane API；不发明plugin pane list／ownership register。
- cold restore先查活身份；空壳不确定保留，创建新受监管tab；避免误关用户输入／任务。
- 退出事件缺失时暴露恢复等级，不把基础模式说成无人值守。

**验收**：并发20次ensure、一半create响应丢失、hook进程随机退出，都不能出现双Gateway；Stop与create并发不会在paused后启动child；handoff PID不变；cold restore环境来自新pane；无关用户pane零修改。

**回滚**：pause并停测试实例，再disable；不删除用户workspace；依据runtime确认只清理自己创建的测试tab。

## 5.6 阶段4：显式 Profile 初始化与 Agent 能力（P0）

新增profile_init、SOUL/skill模板、配置向导和可审阅的初始化摘要。必须可dry-run列路径、字段名、动作而不输出secret。

- 使用04的空白暂存root，不调用clone；初始化目标冲突fail closed；移入失败可回滚且不会覆盖existing Profile。
- 配置只用明确Profile作用域CLI `config set`，凭据通过安全交互，不进入argv／日志；root OAuth fallback的限制可见。
- default paused，未完成expected platform与模型配置不自动start。
- Agent只读Herdr命令通过后，才测试有明确目标的创建／focus／关闭；列出真实tool schema和加载插件，验证权限默认值。

**验收**：fixture中的假secret、记忆、cron、plugins不被复制；default active_profile不变；no alias/service副作用；R2加独立bot R3验证通过；运行身份和Profile home一致。

**回滚**：暂停专用Profile，移除本插件新增模板前核对hash；默认保留用户填写的凭据和历史，不自动删除Profile。

## 5.7 阶段5：无人值守和运维（P1，承诺有界恢复的发布 gate）

增加launchd/systemd模板和安装／移除助手。它们不是首个spike的前置依赖，但在产品宣称“supervisor自失效后无人值守恢复”前必须完成。

- 一个native service只监管owner Herdr；30秒timer只执行同一个短ensure，连接已有server，不触发意外auto-start。
- 实现service/timer归属元数据、预检、暂停、显式卸载；不覆盖用户原有Herdr服务。
- native-managed live handoff未通过spike时，产品明确阻止该操作并提供协调cold restart；不能开KeepAlive后假定兼容。
- 明确正常Stop、Herdr crash、service stop、sleep/wake、logout的差异；timer尊重pause/fuse/disabled和maintenance。

**验收**：supervisor在handoff后退shell、无新focus事件，timer仍发现并恢复；Herdr自身退出后native service按预算恢复；paused不被timer复活；user logout策略与服务安装作用域一致。

**回滚**：pause→确认无child→移除本插件timer／自己拥有的service；保留用户原有Herdr及Profile。

## 5.8 阶段6：安装包、升级和发布（P1）

生成manifest、可执行权限和小型发布包；不把设计仓库当前版本标为可安装。先产出检查通过的实现PR，再更新README状态。

- 版本支持矩阵显式记录Herdr/Hermes SHA、OS、control protocol、state schema。
- 原子升级不在线替换lock文件；maintenance先停机；schema迁移失败保留原文件，不假装可读。
- 删除旧版本前保证原进程已退出；livehandoff兼容与native模式支持分开列出。
- 完成卸载残留测试、日志上限和文档链接；Conventional Commits，显式stage，不跳过hooks。

**验收**： [06全矩阵](06-测试与验证.md) 达到对应模式的DoD；有回滚包与脱敏运行报告；不会修改其他Profile/token。升级支持版本只在新矩阵通过后改动。

**回滚**：保持paused，恢复已知通过的插件版本和本插件schema快照；Hermes数据迁移不可由插件盲目逆转，必要时让专用Profile停留在失败版本并由操作者单独恢复备份。
