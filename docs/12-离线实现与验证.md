控制文件锚定 canonical Profile，XDG/TMPDIR变化不会产生第二把单例锁。所有新Gateway均由pane supervisor通过argv创建，stdin为DEVNULL、stdout/stderr为独立管道、保持相同SID，并使用umask=077。插件不删除Hermes锁、不调用 `--replace`、不启动native Hermes service。

`bind` 只初始化既有专用 Profile 的控制目录。新 Profile 暂存创建/迁入、persona/skill安装、自动孤儿回收、maintenance、卸载/升级助手、service/timer和pane状态UI尚未实现。

## 12.3 测试所证明的行为

| 场景 | 断言与证据 |
|---|---|
| 20路并发ensure | 只发一次workspace.create、一次plugin.pane.open，只启动一个Gateway；不接管同名用户workspace。[controller tests](../tests/test_controller.py) |
| 创建响应丢失 | pane已创建时从runtime/R0找到原实例；workspace结果未知时保留pending，不盲发第二次创建 |
| controller崩溃 | 实际子进程在workspace/pane发送前后退出；发送后状态未知会阻断，已运行supervisor可继续核验 |
| Pause→Resume与迟到pane | 新revision撤销旧generation；迟到旧pane不能spawn，最后仅一个Gateway |
| 释放短锁 | 人为延迟open响应时，新supervisor仍能取得mutation锁、登记runtime并启动fake child |
| Popen与PID登记之间崩溃 | 持久 `spawn_pending` 留存；后续ensure为UNKNOWN，不创建替代实例 |
| handoff模拟 | API改变terminal ID，PID/start/SID及稳定pane IDs不变；更新自己的账本，不重启child |
| cold restore模拟 | 旧owner已退出，API旧pane改为用户shell；保留旧shell，仅在自有workspace创建新受监管tab |
| 退出/重试 | 75更换child但不换supervisor；clean0持久暂停；78只运行一次；连续1六次熔断；其他分类与时间规则见[lifecycle tests](../tests/test_lifecycle.py) |
| Stop/Restart/Resume | 意图先fsync；重复Restart只发一次USR1；Stop期间Resume等旧child退出后再启动。[supervisor tests](../tests/test_supervisor.py) |
| 后台任务 | 假Gateway生成新SID且忽略TERM的任务；停止时按确认的后代指纹执行TERM/KILL，最后child/任务均退出 |
| 慢探测/高输出 | 半帧慢peer、慢Gateway响应及大量stdout/stderr不阻塞Pause；慢日志写入只丢数据并计数 |
| owner失联/disable | 短断连保持child；超出grace停止且保留running；明确disabled持久写paused |
| PID复用/权限 | 旧PID的新指纹不收到信号；旧进程列表里的复用PID必须重新证明父链，不能获准作为后代清理；未知权限不当作absent；原子替换造成已打开文件nlink=0时仍可读合法旧快照 |
| 配置与秘密 | 拒绝Python/身份/行为覆盖、重复字段、非有限JSON数、错误文件权限和恶意pointer；不继承源provider/bot凭据 |

| CLI闭环 | Resume→fake进程READY→Restart→Stop等待完成；普通status=0与require-ready=10区别；不安全launcher拒绝执行。[CLI tests](../tests/test_cli.py) |

## 12.4 当前命令契约

所有命令默认输出JSON。launcher先使用 `--config /absolute/config.json`，未传时读取 Herdr 注入的 `HERDR_PLUGIN_CONFIG_DIR/config.json`；没有配置只报SETUP_REQUIRED。手动从hook之外操作时，通过全局 `--owner-socket /absolute/bound.sock` 提供明确owner context，值必须匹配binding。

| 命令 | 行为 |
|---|---|
| `bind --dry-run`（默认） | 预检既有专用Profile，展示控制目录计划，不创建Profile或启动Gateway |
| `bind --apply` | 显式初始化控制目录，初始paused；已有绑定和意图保持不变 |
| `ensure --source startup/event/timer/manual` | 尊重paused/fused，连接现存Herdr，核验或预留创建；不会自动启动Herdr |
| `start` / `resume` | 预检成功后持久running及budget reset，再ensure；ACK不代表READY |
| `pause` / `stop` | 先持久paused，再通知supervisor；坏模型/YAML不阻止保存Pause |
| `stop --wait 30` | 等待已确认停止；`completed=false`时返回30，孤儿不被报告为停止 |
| `restart` | 只在running时接受，按revision请求USR1；不会隐式Resume |
| `status --json` | 只读状态，命令成功处理即0，包括PAUSED/UNKNOWN |
| `status --require-ready` | 仅READY返回0；其余已读取状态返回10，配置读取失败仍返回错误码 |
| `doctor --json` | 只读检查Profile、固定Hermes版本、owner以及runtime；不执行Hermes CLI或加载其main |
| `logs --lines 50` | 最多读取64KiB、最多200条结构化事件；不导出raw child输出 |
| `supervise` | 仅供Herdr真实argv pane入口；必须有有效generation票据、真实pane context和lifetime锁 |

显式重试动作可传 `--request-id ID --expected-revision N`，两者必须同时提供。最近请求被去重，较旧revision不能覆盖新Pause。hook把BUSY/PENDING/UNKNOWN和非owner作为短正常返回；交互ensure对未知/等待返回10，熔断返回20，操作失败返回30。

本轮未执行这些命令去绑定、安装或启动真实服务。示例字段见 [examples](../examples/README.md)；新 Profile 的真实初始化流程仍在P0-06 gate之后。
