# 08 · 决策记录

状态“采纳”表示本设计选择，不表示已实现。所有ADR受固定版本与 [05 spike gate](05-实现步骤.md) 约束；发现源码或运行证据不符时修改ADR和测试矩阵，不能只在实现里绕开。

<a id="adr-01"></a>
## ADR-01 · Pane-owned supervisor 优先

**采纳**：Herdr plugin controller创建真实argv pane，pane内supervisor启动foreground Gateway；可选native service只监管Herdr。

原因：真实HERDR_*来自Herdr创建pane时注入；普通argv退出不会自动重跑，startup也无监督循环。[H03/H04/H06](09-源码证据索引.md#h03) herdr-proc的外部服务+viewer更适合独立服务，但无法满足核心环境来源和生命周期绑定。[P06](09-源码证据索引.md#p06)

代价：Herdr故障可中断Gateway，不能保证独立可用；需自己的child supervision和restore reconcile。放弃“Gateway必须来自真实pane”或Herdr新增原生监督API时重新评估native Hermes service。

<a id="adr-02"></a>
## ADR-02 · 一个专用 Profile 绑定一个明确 session

**采纳**：首版每机、每OS用户一个 `herdr-control`；配置owner socket/session，默认default。其他session的hook不争抢，不采用先到先得。

原因：同Profile并行Gateway和共享bot token有冲突；Herdr插件状态根不按session分区。[H02](09-源码证据索引.md#h02)、[M09](09-源码证据索引.md#m09) 每session独立Profile可行，但需要独立token、用户入口和凭据维护，当前没有这个需求。

代价：打开named session不会自动获得第二个Gateway。跨session改绑必须显式停旧owner。出现多个明确独立bot/Agent需求时，再扩展为多binding，不复用同token做伪多实例。

<a id="adr-03"></a>
## ADR-03 · 意图、排他与活身份分别取证

**采纳**：持久intent决定能否运行；固定Profile目录中的flock决定排他；活control socket与OS指纹／pane关系决定身份。Hermes自带runtime/token locks是第二道保护，PID文件和label只作hint。

原因：zed提供socket/identity/lock模式，mirror提供lifetime和pause，llmtrim记录state路径漂移的孤儿事故；这些均不足以靠单个PID文件解决。[P02–P05](09-源码证据索引.md#p02)

代价：UNKNOWN有时牺牲自动恢复速度；实现需要明确组合证据。要求同UID恶意隔离时这套身份不够，需要OS边界；上游提供可认证的单例服务API时可简化。

<a id="adr-04"></a>
## ADR-04 · Stop 与 Pause 使用同一个持久暂停语义

**采纳**：MVP Stop/Pause都先持久paused再终止；Start/Resume显式清除；Restart在paused下拒绝。未知故障不写pause；没有更新intent的clean0由supervisor落pause。

原因：用户停止后不应被focus/startup/timer复活；mirror有类似stop=paused行为。[P03](09-源码证据索引.md#p03) Hermes0/1/75还取决于marker和signal，不能只看整数推断人的意图。[M07](09-源码证据索引.md#m07)

代价：没有“临时停止后自动补齐”的Stop含义；计划维护另用有截止时间的maintenance。直接外部停止与supervisor同时死亡的未记录意图无法保证。若产品将来需要临时stop，需新增独立显式动作而非改变现有Stop语义。

<a id="adr-05"></a>
## ADR-05 · 空白暂存 Profile，禁止隐式复制

**采纳**：在独立空白暂存HERMES_HOME中调用官方fresh create，验证后原子迁入目标，再逐项config set与交互凭据；初始paused。不clone、不复制root auth、不自动同步用户skills。

原因：clone包含`.env`和记忆，clone-all本SHA仍可复制cron；即便fresh也会复制整个source model区块。[M02](09-源码证据索引.md#m02) root OAuth fallback及refresh写回使Profile不是凭据sandbox。[M03](09-源码证据索引.md#m03)

代价：多一个初始化暂存与迁移spike，但避免暂时复制secret再删的中间暴露。若Hermes提供明确 `--no-inherit-model` 等纯fresh契约，可去掉暂存步骤；在此之前不能简化为直接从用户root fresh create。

<a id="adr-06"></a>
## ADR-06 · 复用 gateway.sock，分层定义 readiness

**采纳**：基于固定SHA已有identify/status协议1实现R0/R1/R2；业务R3独立。不给Hermes安装新的health Python plugin。

原因：该socket已有活回答、Profile/PID/start/code identity；但绑定先于adapter，running先于finish wiring，platform status可能保留旧writer。[M10/M11](09-源码证据索引.md#m10) 单纯kill0、日志关键词或heartbeat不足。

代价：受当前源码协议限制，升级要重新验证；socket绑失败是UNKNOWN而不是自动再起。将来有稳定公开readiness契约时替换adapter，但仍保留业务链路单独测试。

<a id="adr-07"></a>
## ADR-07 · handoff adopt，cold restore 保守替换

**采纳**：handoff活实例只修本插件账本，不重启；冷恢复走新argv pane，旧shell无充分空闲／归属证据就保留。

原因：snapshot不保存plugin_panes，冷恢复不重放普通argv，stock API不能重登记ownership，也不能证明shell没有用户输入。[H07–H09](09-源码证据索引.md#h07)

代价：可能留额外retired shell；adopt后需普通pane API。不为了布局整洁误关用户任务。上游持久化ownership或提供可靠的恢复状态/空壳标识后，可改善自动清理。

<a id="adr-08"></a>
## ADR-08 · 有界无人值守恢复依赖短 timer

**采纳**：基础plugin只保证已有触发下reconcile；有时限的无人值守模式额外安装30秒短ensure timer。它只连接已存在Herdr Server，不运行Gateway。

原因：handoff后的shell respawn可以绕过pane.exited；没有shutdown hook，事件不是可靠周期心跳。[H06/H12](09-源码证据索引.md#h06)

代价：P1增加OS配置和卸载面；未完成时不承诺无人值守时限。若Herdr提供稳定、低成本、可靠的server tick/watchdog入口，可去掉timer；不另建脱离pane的常驻插件daemon来重复监督。

<a id="adr-09"></a>
## ADR-09 · Native-managed handoff 暂不支持

**采纳**：普通Herdr模式设计支持live handoff；launchd/systemd监管Herdr时先只支持协调cold restart，分OSspike通过后才开放handoff。

原因：Herdr自己detached新server，原生管理器的main PID/cgroup/KeepAlive未必随之移交。[H13](09-源码证据索引.md#h13) 源码未提供跨两套生命周期的运行证明。

代价：native模式升级有短暂停机。不能为了声称handoff可用而禁用整个进程树清理。需要原生管理器友好的handoff契约或真实实验后再改。

<a id="adr-10"></a>
## ADR-10 · 最小可用工具集，不宣称资源硬隔离

**采纳**：专用SOUL/skill、显式platform toolsets、可选插件空allowlist、关闭project plugins和multiplex；保留真实local terminal与Herdr socket以实现控制。

原因：真实控制是任务核心，但terminal/process_manage有广泛权限，Profile不限制文件系统。[M13/M14/M18](09-源码证据索引.md#m13)

代价：仅面向信任当前OS用户及其Agent的场景。严格只允许控制声明pane需受限broker和移除裸terminal，属于另一安全架构，不能靠profile配置冒充。

<a id="adr-11"></a>
## ADR-11 · 失败要可分类，未知身份不试探性启动

**采纳**：1退避前排除ownership冲突；75也有风暴预算；2/78熔断；CLI坏配置另做本插件无副作用预检；创建结果不明保留pending并阻断盲重发。

原因：源码的退出码比“75重启、78全部冲突”复杂，配置guard入口也不完全相同。[M07/M08](09-源码证据索引.md#m07) Herdr create没有被证实具备幂等重放契约。[H05](09-源码证据索引.md#h05)

代价：错误条件下可能需要doctor／人工核查。可证实的上游幂等创建、可认证身份或更精确退出原因接口出现后，可以缩短保守等待，但不能先把不确定等同absent。
