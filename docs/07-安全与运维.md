# 07 · 安全与运维

> Current 0.1.5 scope: the plugin protects launch ownership and process lifecycle. Hermes owns model, credential, tool and access policy; the historical policy recommendations below are not plugin-enforced requirements. See the [Gateway contract](18-Herdr兼容策略.md#hermes-gateway-contract).

本章是拟实施规范。当前只有设计仓库，没有安装任何服务或插件。运维命令需在未来实现并验证对应功能后执行；不能用本章作为已完成安全审计的证明。

## 7.1 威胁模型与信任边界

默认信任本机OS用户、已审计的插件代码、Herdr/Hermes二进制及显式允许的模型／消息平台。防护目标包括误操作、stale state、PID reuse、并发双启动、配置／路径漂移、意外输出secret和不可信聊天／pane内容的prompt injection。

不承诺抵抗具有相同UID文件／进程权限的恶意程序。Gateway有local terminal及真实Herdr socket，能够访问该UID允许的资源；Profile、persona、技能和工具允许列表不能强制只控制某个workspace或禁止读取其他Profile。[H11](09-源码证据索引.md#h11)、[M01/M14](09-源码证据索引.md#m01)

| 边界 | 机制 | 实际限制 |
|---|---|---|
| 远端用户→Gateway | 专用bot、数值用户allowlist/pairing、默认不开放all-users | 不能共享线上bot来测试冲突；被允许用户的消息仍可能含恶意引用内容 |
| 模型→工具 | 窄skill、明确目标、保留审批、禁止旁路生命周期命令 | terminal本身很强；prompt不构成系统授权策略 |
| controller→进程 | UID、canonical path、start fingerprint、nonce、generation、pane membership | 降低误杀和竞态，不能提供跨平台不可伪造的同UID身份 |
| 本地socket→server | Unix socket权限、peer UID可用时验证、字段白名单和deadline | 对同UID不是强隔离；不导出TCP或共享socket目录 |

需要硬隔离时应改为独立OS用户／sandbox，加受限Herdr操作broker并收窄工具；那会改变真实pane环境和控制模型，需另做ADR与spike。不能通过增加一句SOUL规则声称已解决。

## 7.2 文件、socket、lock 和状态安全

1. 先canonicalize明确配置的Profile根并记录；允许操作者明确指定的根本身经验证解析到真实路径，但根下控制目录和文件不接受意外symlink。每次打开校验owner、类型、mode；使用dirfd/openat/O_NOFOLLOW等可用机制避免check-use之间绕路。
2. 私有目录0700，state、日志、配置和socket0600，umask077。解释器和plugin checkout必须不可由其他用户写；launcher从runtime-python读取一行路径，严格引号，不eval、不source，不把路径当shell片段。
3. 数据文件使用同目录随机临时文件，O_CREAT|O_EXCL，写入flush/fsync，rename/replace后fsync parent。失败保留原有效文件。schema新于当前版本、intent损坏或binding不符时fail closed，doctor只读展示。
4. lock文件只创建一次并flock，运行期间不删除、不原子replace；不同inode上的同名锁不会互斥。lifetime FD设CLOEXEC并由supervisor独占，避免child或hook孙进程延长锁生命。
5. 本插件socket优先置于固定Profile控制目录。长路径则用固定短私有目录，例如 `/tmp/herdr-gateway-herdr-<uid>-<binding-hash>/supervisor.sock`，父目录0700、本UID且无symlink；pointer只可指向该绑定的预期位置，不跟随任意路径。
6. Hermes socket另有自己的长路径fallback及gateway.sock.path。[M10](09-源码证据索引.md#m10) client按该SHA算法核对候选、类型、UID、权限及响应identity；fallback在共享temp下的路径不满足更强私有目录保证，受同UID信任模型限制。拒绝不明pointer，不因绑定失败而删除别人socket。
7. state／socket清理必须同时证明旧generation已终止且lifetime可独占获取；在线锁不可删。Hermes自己的gateway.lock、PID、token lock由Hermes管理，本插件不“修复”其锁文件。[M09](09-源码证据索引.md#m09)

## 7.3 进程与信号

使用精确argv token、绝对binary、Profile home、OS fingerprint及Herdr pane/SID关系判断归属。不要使用 `ps | grep hermes`、`pgrep -f gateway`后批量kill。进程枚举可以提供诊断候选，但不直接授予终止权限。[P04/P05](09-源码证据索引.md#p04)

supervisor和Gateway不setsid/detach，保留Herdr pane的SID。Stop对已验证child及后代TERM，25秒后仍活才KILL，再等最多5秒；对每个候选重查fingerprint，ProcessLookupError视为已退，AccessDenied视为未知。不能向包含supervisor自己的PGID盲发KILL。Linux可以用pidfd收窄PID复用竞态；macOS用psutil指纹和重查，仍不得宣称原子无竞态。

工具主动创建的新session、脱离父链的进程可能逃过pane清理。若完全归属可证明，supervisor可以清理；不能证明就报告残留，不扫描整机后任意清场。用户需要强制收拢全部任务时应使用额外OS隔离，超出本首版边界。

Herdr正常清理按HUP/TERM/KILL及250ms等待进行；Herdr SIGKILL不走Drop。[H10](09-源码证据索引.md#h10) 长任务要先经插件有界停止或等待业务完成，再停Herdr；native服务的TimeoutStopSec不能延长Herdr内部已发生的快速pane清理。

## 7.4 凭据与配置

新Profile从空白暂存root初始化，防止fresh create复制source model区块；不自动复制secret/OAuth/cron/skills记忆。[04](04-Hermes专用Profile设计.md) 运行环境不继承Herdr原进程的provider和平台凭据。模型显式选provider，使用独立静态凭据；如允许OAuth共享root，必须明确记录该共享而不是宣称隔离。

凭据只通过专用Profile的安全交互或受控secret设施写入；不进命令参数、Git、console日志、状态schema、persona。不要输出整个`.env/config/auth`或完整environ来排障。`config get`只查询已知非敏感key，`config show`不进入公开报告。

权限变更不能只看config文本：列出最终tool schema、Hermes用户/项目/pip插件、MCP和shell hooks。[M14/M18](09-源码证据索引.md#m14) Hermes 插件的选择、配置及加载策略由用户和 Hermes 管理，本项目不检查 `plugins` 或强制项目插件开关。禁止为自动启动方便开启YOLO、全局hook auto-accept或ignore bad config。

## 7.5 日志和可观测性

| 输出 | 内容 | 保留策略（P） |
|---|---|---|
| Herdr plugin log | hook接受／拒绝、短摘要、request id | 遵循上游200条、每流64KiB；不是持久主日志 [H03](09-源码证据索引.md#h03) |
| `logs/events.jsonl` | time、event、state、code、generation、revision、PID与停止阶段 | 单文件5MiB、当前文件+4份历史；0700目录/0600文件；不含正文、token、raw env |
| `logs/gateway-output.log` | child stdout/stderr，帮助早期启动诊断 | 单文件10MiB、当前文件+2份历史；私有，不通过logs命令公开导出 |
| Hermes自身logs | Hermes日志、adapter/agent异常 | 保留上游策略并检查总占用；不替Hermes在线rename正在使用的文件 |
| pane显示 | 当前只作为supervisor宿主；状态通过status/action查询 | 不回显raw输出；尚未实现pane内状态UI |

stdio读端必须持续排空、内存缓冲有上限；如果磁盘写慢，丢弃额外raw输出并计数，不能卡死Gateway。hook不启动长期后台子进程；所有短子命令的stdin=DEVNULL、stdout/stderr按需捕获并确保退出。不要让pane supervisor继承hook管道。[H03/P05](09-源码证据索引.md#h03)

当前日志队列上限128项，raw每项最多16KiB；两类插件日志合计上限55MiB，不包含Hermes自己的日志。保留份数、慢写入、轮转及私有权限已通过离线测试。

任意第三方raw日志可能包含secret，模式脱敏不能保证完全移除。可公开导出只选择结构化白名单字段；raw日志留本机并需单独审阅。诊断包默认排除config、env、auth、SOUL、memory、session正文和bot身份细节。

本地status至少含：desired/observed state、ready level、owner key简写、Profile、generation、child/supervisor身份、last exit、last probe、expected平台状态、retry_at、fuse reason、恢复模式。轻量计数包括start/restart/adopt/replace、probe失败、丢日志数量、最近transition时间；首版不新增metrics HTTP listener。

## 7.6 排障路径

| 状态／症状 | 先看什么 | 允许动作 |
|---|---|---|
| SETUP_REQUIRED / MISSING_PROFILE | config路径、canonical home、profile ID | 修复明确配置／显式初始化；不改default Profile |
| NOT_OWNER | configured socket与调用session | 切到绑定session，或走显式迁移；不竞争锁 |
| PAUSED | intent.reason/revision | 保持停止；明确需要运行时Resume |
| FUSED code2/78 | 配置预检、平台error_code、version | 修复后Resume；不能循环restart或--replace |
| FUSED restart storm | 最近退出时间和75/1计数 | 查watchdog、依赖、token冲突；不先清计数掩盖问题 |
| UNKNOWN socket timeout | lifetime、PID/start、Herdr membership、socket权限 | 只读diagnose；不得新起第二Gateway |
| DEGRADED | expected平台retrying/fatal、writer身份 | 修网络／token；存活进程交给其reconnect，不无限重启 |
| PENDING_UNKNOWN | generation票据、Herdr snapshot、实际进程 | 核对已创建结果；不能因TTL过期盲重发 |
| handoff后plugin pane not found | 普通pane API、own ledger、原PID | adopt自有账本，验证后普通pane focus/close |
| Herdr重启后旧shell仍在 | 是否是retired空壳、是否有用户输入／任务 | 保留不确定pane，人工清理；单例看Gateway而非标签 |
| 卸载后还有进程 | 是否先pause；runtime/identity是否可验证 | 用保存的明确目标有界停止；不全机kill |

本插件 `doctor/status/logs` 已实现，只读命令和退出码见 [12](12-离线实现与验证.md)。真实环境获准后，也可用 `herdr plugin log list --plugin nocoo.hermes-gateway --limit 20`、`herdr api snapshot`、`herdr pane process-info <已核验ID>` 交叉核对。cherry 的真实接入、READY 和用户消息验证见 [13](13-cherry接入与验证.md)；下面的系统服务与 timer 仍是设计模板。

## 7.7 macOS launchd

可选LaunchAgent只负责Herdr；示例Label `ai.hexly.herdr.owner`，ProgramArguments为 `/opt/homebrew/bin/herdr --session default server`。RunAtLoad=true、KeepAlive=true、ThrottleInterval=5。此处是P1渲染要求，不是已安装的plist。绝对binary、cwd、log路径、XDG环境和所绑定socket必须来自配置，不依赖交互shell PATH。

另一个Label `ai.hexly.hermes-on-herdr.reconcile`：StartInterval=30，KeepAlive=false，拟运行本插件 `--config <绝对config路径> --owner-socket <绑定socket> ensure --source timer`。ensure始终只连接现存Herdr，不含auto-start分支；timer不伪造pane IDs。service/timer模板及安装工具仍属于未实现P1。

以下为rendered plist已审核、对应路径变量已设置后的native命令，不是本轮执行记录：

```sh
: "${HGH_LAUNCHD_PLIST:?本插件生成并核验的plist绝对路径}"
plutil -lint "$HGH_LAUNCHD_PLIST"
launchctl bootstrap "gui/$(id -u)" "$HGH_LAUNCHD_PLIST"
launchctl print "gui/$(id -u)/ai.hexly.herdr.owner"
launchctl print "gui/$(id -u)/ai.hexly.hermes-on-herdr.reconcile"
```

图形用户LaunchAgent依赖用户登录，不是开机前全局daemon；无GUI会话需另验证适用launchd domain。KeepAlive会在server退出后拉起，因此停止native-managed Herdr要先插件Pause，再bootout对应job；单独 `herdr server stop` 可能被立刻恢复。操作前记录原desired，维护完成只恢复原本running的实例。

Herdr live handoff另起detached server，KeepAlive可能与新owner竞争。[H13](09-源码证据索引.md#h13) 未通过专门spike时此模式只支持协调cold restart；不提供看似“一行搞定”的live handoff服务配置。

## 7.8 Linux systemd

使用user service；示例渲染内容（P，绝对路径需要安装器替换）：

```ini
[Unit]
Description=Herdr owner session for Hermes Gateway
StartLimitIntervalSec=300
StartLimitBurst=6

[Service]
Type=simple
ExecStart=/absolute/path/herdr --session default server
Restart=on-failure
RestartSec=5
TimeoutStopSec=35
KillMode=control-group

[Install]
WantedBy=default.target
```

文件名拟为 `herdr-owner.service`。另建 `hermes-on-herdr-reconcile.service`，Type=oneshot、TimeoutStartSec=10，明确config目录，执行短ensure，不启动Herdr；timer如下：

```ini
[Unit]
Description=Reconcile pane-owned Hermes Gateway

[Timer]
OnBootSec=30
OnUnitActiveSec=30
AccuracySec=1
Unit=hermes-on-herdr-reconcile.service

[Install]
WantedBy=timers.target
```

经渲染和核对后可执行：

```sh
systemctl --user daemon-reload
systemctl --user enable --now herdr-owner.service
systemctl --user enable --now hermes-on-herdr-reconcile.timer
systemctl --user status herdr-owner.service hermes-on-herdr-reconcile.timer
```

退出登录后继续运行取决于user manager及linger；若需要，单独配置并验证 `loginctl enable-linger "$USER"`，不由plugin startup暗改系统策略。`Restart=on-failure`尊重正常server stop，但systemctl stop并不自动给予Gateway更长drain：需先通过插件停止。

systemd cgroup/main PID与Herdr自detached handoff的组合也需spike；不要靠KillMode=process故意泄露children来“解决”handoff。未验证时native-managed模式只cold restart。服务启动后Gateway自己的环境要去掉INVOCATION_ID等残留，使其正确识别为external supervisor。[M10](09-源码证据索引.md#m10)

## 7.9 升级、卸载和所有权迁移

升级顺序：记录原intent→maintenance／pause→确认child和必要supervisor结束→备份本插件schema→替换代码→预检固定兼容接口→恢复原running意图→R2/R3。停机窗口内也不unlink正在持有的lock。Hermes更新单独安排，不能由plugin startup执行；Profile数据迁移失败不盲目回滚用户数据库。

推荐卸载顺序：Stop/Pause并确认无child→停本插件timer→停止supervisor并确认lifetime释放→关闭已核验自有pane→删除自己拥有的native job（若无其他用户依赖）→Herdr plugin uninstall。Herdr自身不会在unlink时停pane。[H12](09-源码证据索引.md#h12)

native资源只按记录的Label/unit、文件hash和配置路径移除，绝不搜索“herdr”名字批量删除。共享或用户原有Herdr service保留。插件的pause tombstone和专用Profile默认保留，重新安装仍尊重停止意图；删除凭据／历史是独立操作。

跨session迁移或改Profile路径：先停止旧owner并确认无旧进程，备份binding/state，检查新socket可达和无冲突，再显式重绑。机器级共享bot token不做自动主备切换；网络分区时本地锁无法防止另一台机器使用同token，需另行设计外部租约，首版不支持。
