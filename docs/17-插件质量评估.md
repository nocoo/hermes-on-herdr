# 17 · 插件质量评估与回归测试

2026-09-12，基于 `bba170702b47e7d5b7d9d3a5351e3306cf48e7d9` 做 ponytail 评估。新增 **19 项测试**，先复现再修复 **9 类问题**；最终 **186 项测试**在 macOS 的 Python 3.11.15、3.14.7 均通过。业务代码净增 6 行，没有新增运行时依赖。

Controller 的短事务协调、supervisor 的进程监管、固定 inode 锁、持久化 Pause、进程指纹复验，以及独立显示进程都有实际故障场景支撑，应保留。本轮将 pending 票据校验集中到 Store，删除 controller 中的重复校验；继续使用现有 unittest、socket/进程 fixtures、psutil 和 PyYAML。

## 发现与修复

| 问题 | 原行为 | 修复后与回归入口 |
| --- | --- | --- |
| 控制请求 `verb` 为数组或对象 | 未捕获的 TypeError 使 supervisor 退出，连带停止 Gateway | 返回 `UNSUPPORTED_VERB`；原 child 继续存活，随后仍可 Pause。[supervisor tests](../tests/test_supervisor.py) |
| 控制回应 `code` 为数组或对象 | 可选通知的解析错误掩盖已持久化的 Pause | 归一为 `PROTOCOL_ERROR`，Pause 仍返回 accepted、notified=false。[RPC](../tests/test_rpc.py)、[controller](../tests/test_controller.py) |
| 注册记录缺失 `plugin_root`、空值或相对路径 | 缺失值可借用当前目录通过归属检查 | 必须提供无控制字符的绝对路径；有效 checkout symlink 别名仍受支持。[RPC tests](../tests/test_rpc.py) |
| `.env` 的单引号键、UTF-8 BOM、CR 换行 | 可绕过 `HERDR_*`、`HERMES_HOME` 等禁止覆盖检查 | 按上游接受的键写法扫描并拒绝覆盖；合法密钥引用保持可用，文件不被改写。[config tests](../tests/test_config.py) |
| `terminal.cwd` 缺失、空值或相对路径 | 预检结果取决于调用者当前目录 | 必须显式指定与配置一致的绝对目录。[config tests](../tests/test_config.py) |
| `events.jsonl` 是无 writer 的 FIFO | `logs` 无限等待打开文件 | 非阻塞打开后拒绝非普通文件，返回 `UNSAFE_PATH`。[CLI tests](../tests/test_cli.py) |
| Hermes `gateway.lock` 是无 writer 的 FIFO | 状态检查卡住，启动前检查也可能停滞 | 非阻塞检查，状态为 `UNKNOWN`，保留 FIFO，Pause 可用。[CLI tests](../tests/test_cli.py) |
| 损坏的意图枚举或 pending 票据 | TypeError 外逃，或损坏票据通过底层读取 | 所有 Store 读写统一拒绝为 `STATE_SCHEMA`，保留原文件，不创建资源。[state](../tests/test_state.py)、[controller](../tests/test_controller.py) |
| 过深 YAML | RecursionError 外逃 | 转为脱敏的 `CONFIG_ERROR`，保留配置原文。[config tests](../tests/test_config.py) |

另补充配置字段/策略段类型、URL 内嵌凭据、重复插件注册、协议版本/回应类型、原子 replace 失败等断言。文件检查使用真实 FIFO；控制请求使用真实 Unix socket；supervisor 回归使用真正的隔离进程，验证存活、唯一 child、意图保持及最终停止。

`.env` 行为依据固定 Hermes [env_loader.py](https://github.com/NousResearch/hermes-agent/blob/b7ac3ba1cdf89f94dfe86de27e01358b194f4053/hermes_cli/env_loader.py) 和该版本锁定的 [python-dotenv 1.2.2 parser](https://github.com/theskumar/python-dotenv/blob/v1.2.2/src/dotenv/parser.py)。只读取上游源码，并以无凭据字符串核对 parser；没有加载真实 Profile 的 `.env` 或执行 Hermes 入口。

## 复现

在仓库根目录创建独立、使用解释器副本的测试环境：

```sh
python3.14 -m venv --copies .cache/quality/venv
uv pip install --python .cache/quality/venv/bin/python -r requirements.txt
.cache/quality/venv/bin/python -I -B tests/run.py
```

将解释器换为 Python 3.11、使用另一 venv 路径即可核验最低支持版本。可选的完整覆盖率采集：

```sh
uv pip install --python .cache/quality/venv/bin/python 'coverage==7.16.0'
.cache/quality/venv/bin/python -I -B tools/test_coverage.py
uvx --from 'ruff==0.16.7' ruff check --select E9,F63,F7,F82 src tests tools/test_coverage.py
```

[test_coverage.py](../tools/test_coverage.py) 为每次运行创建 `.cache/coverage-*`，保存日志及 JSON 报告。它只在该独立 venv 中临时安装 `.pth`，在测试结束后移除，用于采集会清空环境变量的 CLI/supervisor 子进程；无需放宽产品的 child environment 白名单。普通 `coverage run tests/run.py` 会漏掉这些子进程，不宜用于此仓库的完整覆盖率对比。

采集包含 `_exit`/`execv` 前的数据保存；SIGKILL 无法刷新计数，因此覆盖率仍是已采集执行路径的度量。它不代表没有缺陷，也不能替代真实上游集成。后续质量工作应优先验证 Linux 的专有路径与真实 Herdr/Hermes/channel/model 往返；本轮只运行隔离 fixtures，没有操作在线 Gateway、真实凭据、其他仓库、视频或 Release。

现有后代进程轮询可能漏掉两次采样间已脱离父链的任务。该上限仍见 [supervisor.py](../src/hermes_gateway_herdr/supervisor.py) 的 `ponytail:` 注释；需要主机级收容验证才能提升保证，增加单元测试不能证明任意后台任务均被回收。
