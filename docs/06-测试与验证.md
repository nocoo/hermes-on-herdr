# 06 · 测试与验证

本章规定未来实现的测试；本轮实际完成的仅是源码／文档／发布检查，见 [11](11-研究与验证记录.md)。本轮未启动测试Server/Gateway、未创建Profile，也没有运行下述故障注入。

## 6.1 测试分层和环境

单元测试覆盖锁、身份、意图和时间规则；集成测试使用假Herdr RPC／假Gateway验证竞态；E2E在隔离Herdr session和独立Profile中验证真实PTY/信号/恢复；业务E2E另用独立测试bot。测试命令不得作用于default Profile或当前用户线上Gateway。

macOS与Linux都需有运行报告。Linux用普通host或VM验证首版host路径，不用s6容器结果代替；native service/handoff单独分组。无真实token时只能通过R0/R1和负向R2，不能标业务成功。

每个有进程的用例前后保存脱敏的：OS、组件version/SHA、binding/generation/intent revision、PID+start fingerprint+SID、Herdr IDs、R0/R1/R2结果、计数、单调时间线、cleanup结果。任何线上Profile内容不进入fixture或仓库；fake secret使用明确哨兵字符串，不用真实值。

### 测试环境门禁

- 使用独立OS测试用户最佳；否则独立XDG_CONFIG_HOME/XDG_STATE_HOME、测试session、Profile根、bot token，全部显式设置，断言和生产路径不同。
- `HGH_TEST_*`变量必须非空；PID从测试状态取出后用doctor的身份断言确认，不能手填随意PID后直接kill。
- crash脚本先登记测试资源，再注入；cleanup检查实例identity，不使用 `pkill hermes`、`killall` 或按模糊字符串杀进程。
- `HERMES_GATEWAY_LOCK_DIR`与生产隔离只允许在**完全独立测试凭据**的测试环境；生产部署不得用更换token lock目录绕过冲突。
- 虚拟时钟只用于单元／fake集成，真实进程timeout使用monotonic和有界轮询，不靠一次长sleep断言。

## 6.2 单元矩阵

| ID | 场景 | 关键断言 |
|---|---|---|
| U01 | canonical path、UID、owner socket哈希 | symlink别名不生成两把锁；PID/inode/焦点变化不改owner_key |
| U02 | flock并发、lock inode不变 | 仅一个lifetime owner；lock file不被replace/unlink；child不继承FD |
| U03 | 原子state、disk full、fsync失败、truncated JSON | 不读半JSON；pause写失败不能成功ACK；损坏意图fail closed |
| U04 | stale PID／PID reuse／权限错误 | start不同绝不kill；EPERM/AccessDenied不是absent；wallclock startedAt不当fingerprint |
| U05 | desired revision和旧child退出竞争 | Stop先落盘；旧0不能覆盖新Resume/Restart；旧request replay无额外动作 |
| U06 | 75/1/0/2/78/负signal/未知code | 分类符合03；1+ownership conflict不重试抢锁；未知positive默认fuse |
| U07 | backoff/jitter/熔断跨进程重建 | 1→2→4→8→16→30；限速上界成立；重建pane不能清失败预算 |
| U08 | 协议、超长帧、无换行、慢peer、错误id/version | 有界拒绝；不阻塞child wait；不透传secret／任意命令 |
| U09 | ready状态、旧writer、假socket、heartbeat单位 | live回答但旧connected记录仍not-ready；不把kill0/heartbeat当ready |
| U10 | Profile初始化和env过滤 | source model假secret/cron/auth不复制；不改active_profile；真实HERDR字段保留，来源secret/Python/native markers清理 |

这些是行为和故障边界测试，不为每个getter或常量写镜像测试。schema和时间模拟尽量复用真实解析器与标准库锁行为。

## 6.3 假进程集成矩阵

| ID | 场景 | 注入方法 | 判定 |
|---|---|---|---|
| I01 | double hooks | 同时20次ensure／focus | 一张pending票据，一次pane create，最多一个child |
| I02 | create响应丢失 | 服务端创建后关闭连接 | 后续按generation找到原实例；不盲重发 |
| I03 | 创建前后controller crash | 在reserved/workspace_requested/pane_requested各点终止controller | 有已知结果则收敛；不明则PENDING_UNKNOWN，无第二实例 |
| I04 | Stop与spawn交错 | pause在RPC前、pane启动前、child spawn前发生 | 最新intent不被覆盖；最多短暂旧child，最终paused且不再spawn |
| I05 | socket未启动、绑失败、stale socket | lifetime仍held，控制server超时 | UNKNOWN；不删held lock、不新起Gateway |
| I06 | fake child各种退出 | fixture控制exit 75/1/0/2/78；稳定300秒后再失败 | 75换child、0pause、fatal单次、backoff与重置符合预算 |
| I07 | 卡住stdin/stdout/stderr | 大量输出、慢日志磁盘、孙进程保留fd | hook5秒内结束；child pipe持续排空；内存／日志有上界 |

| I09 | runtime/state路径漂移 | 改XDG/TMPDIR，保留同canonical Profile | 两次ensure竞争同一lifetime；仍能发现旧实例 |
| I10 | 未来schema/损坏intent/旧revision | 注入未知schema和不一致binding | FUSED或拒绝；不回写破坏原始证据 |

## 6.5 上游真实命令与判定方法

以下为后续隔离测试的可复制命令。先手动设置通过检查的HGH_TEST变量；当前仓库只含设计，未提供下列测试plugin或runtime。

只读版本、layout、进程和plugin日志：

```sh
herdr --version
hermes --version
: "${HGH_TEST_SESSION:?必须是隔离测试session}"
: "${HGH_TEST_PANE_ID:?必须来自测试pane账本}"
herdr --session "$HGH_TEST_SESSION" api snapshot
herdr --session "$HGH_TEST_SESSION" pane get "$HGH_TEST_PANE_ID"
herdr --session "$HGH_TEST_SESSION" pane process-info "$HGH_TEST_PANE_ID"
herdr --session "$HGH_TEST_SESSION" plugin log list --plugin nocoo.hermes-gateway --limit 20
```

隔离测试plugin已经实现、注册且配置完成之后，创建命令语法：[H05](09-源码证据索引.md#h05)

```sh
: "${HGH_TEST_PLUGIN_ROOT:?测试plugin绝对路径}"
: "${HGH_TEST_CWD:?测试工作目录}"
herdr --session "$HGH_TEST_SESSION" plugin link "$HGH_TEST_PLUGIN_ROOT" --disabled
herdr --session "$HGH_TEST_SESSION" workspace create --cwd "$HGH_TEST_CWD" --label 'Hermes Gateway Spike' --no-focus
```

正常产品应由controller创建pane。仅阶段0验证argv primitive时，在已启用的测试plugin中使用下面的手工API等价CLI；不能将其当成绕过controller的日常启动命令：

```sh
: "${HGH_TEST_WORKSPACE_ID:?从测试workspace create结果读取}"
herdr --session "$HGH_TEST_SESSION" plugin pane open --plugin nocoo.hermes-gateway --entrypoint gateway --placement tab --workspace "$HGH_TEST_WORKSPACE_ID" --cwd "$HGH_TEST_PLUGIN_ROOT" --no-focus
```

阶段0的spike entrypoint可以回显环境；正式supervise要求pending/generation，故这条裸调用应被正式runtime拒绝。两个场景不能混用。

动作、handoff和计划停止：[H05/H13](09-源码证据索引.md#h05)

```sh
herdr --session "$HGH_TEST_SESSION" plugin action invoke status --plugin nocoo.hermes-gateway
herdr --session "$HGH_TEST_SESSION" plugin action invoke pause --plugin nocoo.hermes-gateway
herdr --session "$HGH_TEST_SESSION" plugin action invoke resume --plugin nocoo.hermes-gateway
herdr --session "$HGH_TEST_SESSION" server live-handoff
herdr --session "$HGH_TEST_SESSION" server stop
```

每条单独作为相应用例执行，不能顺序运行后称为所有case都通过。actions异步返回的上游log ACK不是最终成功，须检查plugin日志和本插件status。

仅在测试identity guard通过后注入信号（POSIX真实命令）：

```sh
: "${HGH_TEST_GATEWAY_PID:?先核验测试PID和start fingerprint}"
kill -USR1 "$HGH_TEST_GATEWAY_PID"
```

E03另一次用例可用 `kill -TERM "$HGH_TEST_GATEWAY_PID"` 或 `kill -KILL "$HGH_TEST_GATEWAY_PID"`；E17只对已核验的 `HGH_TEST_HERDR_PID` 用SIGKILL。不要用这组命令取代正式Stop/Pause，它们未持久化用户意图。PID reuse用mock和受控fixture验证，不在生产机制造大量进程竞态。

Hermes只读状态参考（工具可能显示native service提示，不将文本当R2）：

```sh
: "${HGH_TEST_PROFILE_HOME:?隔离测试Profile绝对路径}"
: "${HGH_TEST_PROFILE_ID:?隔离测试Profile ID}"
env HERMES_HOME="$HGH_TEST_PROFILE_HOME" hermes -p "$HGH_TEST_PROFILE_ID" gateway status --deep
```

最小socket探测应发两种真实协议帧，逐条新连接、有2秒deadline和响应上限，并匹配id：

```jsonl
{"protocol":1,"id":"probe-identify-unique","verb":"identify"}
{"protocol":1,"id":"probe-status-unique","verb":"status"}
```

这里只给wire格式，newline framing和字段判定由 [02 R0–R3](02-系统架构.md) 规定。probe不能仅打开socket就返回healthy；必须比较home/PID/start、answering_pid、platform writer和期望平台state。长路径pointer、bind失败、unknown协议分别有负向用例。[M10/M11](09-源码证据索引.md#m10)

未来测试入口命名约定：单元可用 `python -m unittest discover -s tests/unit`；集成和E2E入口在实现PR中提供完整help、fixture前提及身份guard。当前没有这些测试文件，不能现在运行该命令并报告“通过”。

## 6.6 安全与故障注入补充

| 故障 | 注入 | DoD |
|---|---|---|
| Profile/state symlink | fixture中替换文件或父路径 | 拒绝越界读写／unlink，不跟随到其他Profile |
| world-writable目录／错误UID | fixture权限变化 | 不创建socket/lock，不将权限错误当stale |
| Unix socket路径超限／恶意pointer | 指向非预期路径／普通文件 | UNKNOWN；不unlink他人文件；不盲跟随pointer |
| 磁盘满／fsync失败／日志超量 | 故障文件系统或mock | pause不假ACK，日志有上限，进程不死锁 |
| source model中有假key／已有cron | 仅fixture哨兵 | fresh暂存初始化后目标不含哨兵和任务 |
| bot未知用户／prompt injection | 测试账号发送越界请求 | 平台allowlist拒绝或pairing；模型不应执行，仍承认persona不是hard sandbox |
| 跨session／跨Profile请求 | 非owner hook或伪造请求字段 | NOT_OWNER／拒绝，不清pause和锁，不改变其他资源 |
| upgrade during run／uninstall first | 测试checkout被替换或unlink | 旧实例可观测地停止；不产生新孤儿，用户数据保留 |

## 6.7 发布判定

P0完成必须有所有P0用例的实际结果，包含业务R3才可宣称可用Gateway；无测试bot时标记“生命周期验证完成，业务链路未验证”。无人值守承诺还需P1 timer/service gate。native live handoff只在对应OS实测通过后加入支持矩阵；其他模式可按已证范围发布。

出现双Gateway、非目标进程被signal、pause丢失、secret进入可公开日志、错误Profile fallback中的任何一个，均阻止发布；不能靠README免责声明代替修复。没有运行的case必须写NOT RUN和缺少的环境，不能把源码阅读标成PASS。
