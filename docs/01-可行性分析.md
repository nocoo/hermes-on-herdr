# 01 · 可行性分析

## 1.1 结论与适用条件

总体结论：**feasible with constraints／有约束可行**。Herdr v0.9.0 有足够的外部命令和 argv pane 能力；Hermes v0.21.1 有 foreground Gateway、外部监督标记、退出码和活控制 socket。缺少的是两者之间负责身份、意图、恢复和去重的 Herdr plugin。源码依据分别为 [H03–H06](09-源码证据索引.md#h03)、[M06–M11](09-源码证据索引.md#m06)。这证明值得实施 spike，不证明设计已经在真实 PTY、bot 或 OS 服务中运行成功。

| 判断 | 能力／要求 | 条件或反证 |
|---|---|---|
| feasible | 通过 Herdr plugin argv pane 启动 supervisor，继承真实 HERDR_* | H04 已有注入和 argv spawn；不能改成 pane run |
| feasible | 专用 Profile、独立 Gateway 状态与 PID | M01/M09；必须唯一规范化 HERMES_HOME，禁用 multiplex 服务该 Profile |
| feasible | 外部 supervisor 处理 child crash、75 restart、有界重试 | M06/M07；需要本插件实现，不由 flag 自动提供 |
| feasible with constraints | live handoff 保留现有 Gateway 并去重 | H08/H09；adopt 自己账本，无法恢复 Herdr 私有 ownership 登记 |
| feasible with constraints | 冷恢复自动重建运行环境 | H07/H08；恢复的是 shell，需要核验后替换／新建，可能保留无法安全删除的旧空壳 |
| feasible with constraints | 用户 Stop 后保持停止 | 通过插件动作先持久写 pause，再发信号；进程同时被外部杀死时不能凭空恢复未记录的意图 |
| feasible with constraints | 无人值守恢复 supervisor 自身失效 | handoff shell fallback 可能不发退出事件；有界恢复需要 OS 定时短 ensure |
| feasible with constraints | Herdr 崩溃后 Gateway 同停、自愈 | SIGKILL／PTY 行为待 spike；接受恢复期间不可用；需要 Herdr 本身被外部恢复 |
| feasible with constraints | Gateway readiness | 控制 socket + 身份 + running + expected platform connected；业务 E2E 另测 |
| not feasible | 仅靠一次 startup hook 获得完整监督和冷恢复 | hook 无 restart loop，冷恢复不重放 argv，普通 pane 退出关闭 |
| not feasible | 普通外部服务同时保留“来自当前真实 pane”的环境与 pane 生命周期 | 从 native service 手写 HERDR_* 只是复制值，缺少创建归属与 PTY 生命周期 |
| not feasible | stock API 重新登记 handoff 旧 pane 的 plugin ownership | 没有此 API；plugin pane focus/close 会找不到旧记录 |
| not feasible | Profile/persona 阻止同 UID terminal 访问其他文件、Profile 或 session socket | Profile 不是 sandbox；真实 Herdr socket 也无 pane 级 ACL |
| not feasible | Herdr 关闭时保证任意长任务完成且永不中断 | PaneRuntime 清理窗口短；突然掉电／SIGKILL 没有事务级任务迁移 |

这里的 not feasible 指在所给基线及约束内无法承诺，不表示修改 Herdr 或引入 OS 隔离后仍无法实现。

## 1.2 版本与调查方法

Herdr 本机 `herdr 0.9.0`，reference HEAD/tag 都是 `b99002ac99b09e00b4ca692436cb15a6b0d676f1`。Hermes 本机 `v0.21.1 (2026.9.7) · upstream b7ac3ba1`，完整提交 `b7ac3ba1cdf89f94dfe86de27e01358b194f4053`。安装源有514个 upstream commits 待更新的提示；本轮没有更新，不能按在线主干推断当前运行行为。[实际记录](11-研究与验证记录.md)

调查亲自读取了 manifest parser、plugin runtime、pane 创建／env、session snapshot/restore、handoff、退出清理，以及 Hermes 的 profile 路由、gateway CLI/restart/shutdown、锁、控制 socket、工具／插件加载。六个指定同类仓库均记录固定 SHA，并重新执行 GitHub exact/near 查询。官方文档用于公开契约；关键分支均以 [源码证据索引](09-源码证据索引.md) 的固定路径复核。

## 1.3 对既有调查线索的修正

| 线索 | 复核后的结论 | 设计影响 |
|---|---|---|
| hook 不是 supervisor，多个 entry 有竞态 | 确认；entry 分别线程 spawn，且没有超时 | 单 startup entry；所有触发进入同一 mutation 协议；hook 有短 deadline，不能后台遗留继承管道的进程 [H03](09-源码证据索引.md#h03) |
| argv pane 退出不会重跑 Gateway | 普通创建确认；handoff 导入后还可能退回 shell | supervisor 内重启 Gateway；补足 supervisor 自身失效的周期 ensure [H06/H08](09-源码证据索引.md#h06) |
| 冷恢复 fresh shell，handoff 丢 ownership | 确认，但 saved launch_argv 仍保存在 snapshot | saved argv 是线索，不是冷启动执行承诺；adopt 只修自己的账本 [H07–H09](09-源码证据索引.md#h07) |
| 持久化 crash window 约5秒 | debounce 会被后续变更继续推迟 | 自己落 pending/runtime；即使 Herdr 没保存 pane 也能识别残留实例 [H07](09-源码证据索引.md#h07) |
| Hermes 没有公开 health socket | 当前 SHA **已有 gateway.sock 协议1**；官方正文未承诺其长期稳定性 | 直接用 pinned socket adapter；无需新增 Hermes health plugin [M10/M11](09-源码证据索引.md#m10) |
| 75=user restart；78=所有 ownership conflict | 75也来自 watchdog；同 Profile 冲突可返回1；混合 fatal/transient 可存活 degraded | 退出码结合原因和活身份；75也限速，1不能盲重试抢锁 [M07/M08](09-源码证据索引.md#m07) |
| 2=config corruption | 模块 main 有此 guard；所选 CLI 路径未见同一调用 | 插件自己的预检必须 fail closed；精确 CLI 坏配置出口待 spike [M08](09-源码证据索引.md#m08) |
| no-skills=零 skill；clone-all 不含 cron | no-skills 保留 essential `hermes-agent`；固定 clone-all 仍可复制 cron | fresh 初始化，核查实际 skill 清单，禁止自动 clone [M02/M05](09-源码证据索引.md#m02) |
| fresh create不会复制原配置 | `_seed_model_config`仍复制整个来源model区块 | 在独立空白暂存根fresh create后迁入，避免model中潜在secret随带；先spike [M02](09-源码证据索引.md#m02) |
| Profile 可以完全隔离登录态 | 可回退 root OAuth，refresh 会写回来源 | 明确静态独立凭据；不复制 OAuth；不声称是凭据 sandbox [M03](09-源码证据索引.md#m03) |
| 现有 herdr-agent-state 已集成 Hermes | 只处理 cli/tui/desktop/acp 对话恢复 | 可保留，但不能替代 Gateway 生命周期管理 [H15](09-源码证据索引.md#h15) |

## 1.5 方案比较

| 方案 | 真实 pane 环境 | 生命周期／恢复 | 成本与结论 |
|---|---|---|---|
| startup 直接 foreground gateway | hook context 是焦点，不是专用 pane | hook 长占；没监督；stdio 风险 | 否决 |
| plugin pane 直接 gateway run | 有 | 75使进程退出，普通 pane 关闭；冷恢复不执行 argv | 仅可做取证 spike，不能交付 |
| shell 无限 while true | 有 | 把0、2、78都复活；无 sticky intent、身份和退避 | 否决 |
| native Hermes service + Herdr viewer | service 没有创建时的真实 pane 环境 | 独立服务可靠，但 Herdr 不在仍运行 | 若将来放弃核心约束可重新评估 |
| 每 session 同 Profile gateway | 每 pane 有 | token/PID 冲突、不可预测抢占 | 否决；不能共享 Profile/token |
| 每 session 独立 Profile/token | 有 | 可行，但凭据、平台入口和路由数量增加 | 后续明确多实例需求才做 |
| 绑定一个 session 的 pane supervisor | 有 | 能处理 Gateway child 生命周期；handoff/cold restore 由 controller reconcile | **推荐**；可选 native Herdr service + 必需于无人值守模式的 ensure timer |
| 修改 Herdr 原生 supervisor／ownership restore | 有 | 可以消除部分 stock API 缺口 | 不在本轮及首版插件范围；未来 upstream 改进方向 |

## 1.6 恢复保证分层

1. **基础插件模式**：owner session 启动自动 ensure；Gateway child crash 由存活 supervisor 直接恢复；startup/focus/退出事件触发 pane 重建。若 supervisor 在 handoff 后退回 shell且没有新事件，恢复等待下一次触发，**没有无人值守时限保证**。
2. **无人值守模式**：加 OS 管理的 Herdr 和每30秒一次短 ensure。timer 只连接已存在的 owner server，不自己运行 Gateway、不伪造 pane IDs。健康条件下 supervisor 失效发现目标≤35秒，重新启动总时限另加 stop/ready budget。OS 休眠、磁盘耗尽、系统服务禁用时不承诺墙钟时限。
3. **原生服务 + live handoff**：先不承诺兼容。Herdr handoff 另起 detached server，原生服务管理器可能重启旧主进程或清理 cgroup；需 macOS/Linux 分别 spike。未通过时只做协调 cold restart。[H13](09-源码证据索引.md#h13)

## 1.7 阻断项与接受的风险

| 风险 | 首版应对 | 放行标准 |
|---|---|---|
| Herdr SIGKILL 后留下 Gateway，仍占 token | 不因 socket 失联马上另起；查活身份；同 Profile 锁兜底 | 隔离 session spike：身份明确、至多一个 child；残留可安全停止 |
| handoff old process 活着但 pane 登记丢失 | own ledger adopt；普通 pane API；启动前双层 fence | Gateway PID/start fingerprint 不变，没有第二 pane/Gateway |
| create RPC 响应丢失 | pending generation 先持久化；禁止盲重发 | orphan/pending 重扫能收敛；不以重复创建换“可用” |
| bad token 只 degraded 不退出 | expected platform 判定失败，保持可诊断、不制造重启风暴 | 不标 ready；明确平台错误和人工修复步骤 |
| 配置／协议升级不兼容 | version capability check + fail closed | 新版本通过矩阵前不自动提升支持版本 |
| 同 UID 越权或脱离 session 的工具进程 | 限定受信任本机 Agent；操作策略与 OS 权限如实说明 | 不把 persona/lock 说成安全隔离；严格隔离列为另一架构 |
| 自动删除冷恢复 shell 误伤用户任务 | 多重证据；不确定则保留，必要时阻断 | 任何身份不明资源不被关闭／杀死 |

最先完成 [05中的最小 spike](05-实现步骤.md)，用 [06矩阵](06-测试与验证.md) 产出真实报告，再决定是否开始完整 runtime。任何需要改 Herdr 全局恢复策略、共享现有 bot token 或复用默认 Profile 才能通过的实现都不算满足本设计。
