## 1. Kokoro 许可

### 1.1 总判断

`hexgrad/Kokoro-82M` 与 `hexgrad/Kokoro-82M-v1.1-zh` 的**模型权重**标了 Apache 2.0。作者欢迎把模型用于生产 / 商业 API。这不等于预置音色身份已清，也不等于生成音频可无限制商用再分发。

Apache 2.0 授予的是 Work（权重 / 代码）的版权与专利许可，排除商标，且不保证不侵权。它没有单独写「生成音频归使用者、可商用再分发、不含第三人声纹或商标」。

### 1.4 音色专项

#### `zf_001`（本片实际选择，v1.1-zh）

- 存在于 v1.1-zh `voices/zf_001.pt`；官方 `make_zh.py` 与 `samples/HEARME_zf_001.wav` 用此声。
- 模型卡把中文 100 说话人归于龙猫数据「免费且无偿 / freely and permissively granted」。
- **没有**可独立核验的龙猫许可文本、说话人协议或再分发条款。
- 编号声避开了微软 Azure Neural 的 `Xiaobei` / `Xiaoni` / `Xiaoxiao` 等商品名，风险低于 v1.0 那组中文名。
- 对可公开发布宣传片：作者陈述好于 v1.0 中文名，仍不是「已公示、可引用的明确商用授权」。公开再分发应视为**有作者许可声称、无第三方公示文本**。

#### `zf_xiaobei` / `zf_xiaoni`（v1.0，本片未选用）

VOICES.md：普通话女声，质量 C / 时长 MM minutes / 总分 D，无来源、无 CC BY。仅存在于 v1.0。

微软官方目录存在同名 Neural 音色（事实并列，不是作者承认「就是 Azure 音色」）：

- `zh-CN-liaoning-XiaobeiNeural`
- `zh-CN-shaanxi-XiaoniNeural`

同表还有 `zf_xiaoxiao`、`zf_xiaoyi`、`zm_yunjian`、`zm_yunxi`、`zm_yunxia`、`zm_yunyang`，与微软 `Xiaoxiao` / `Xiaoyi` / `Yunyang` 等命名同一套。结合 v1.0 模型卡 “closed TTS models from large providers”，不能把这些预置中文声当成无权利瑕疵的合成声。

**本片不使用这组音色。** 若稿面或旧讨论仍出现 xiaobei/xiaoni，按误用处理。

#### `af_heart`（v1.0）

VOICES.md：美式女声，总分 A，无 Training Duration、无 CC BY、无数据集 URL。官方示例默认 `voice='af_heart'`。来源无法从官方材料还原。v1.1-zh 无此声。

若英轨使用 v1.1-zh，对应预置英声是 `af_maple` / `af_sol` / `bf_vale`（众包合成英语，各约 1 小时；作者同样主张 USCO 合成数据无版权 + 不受 ToS 约束）。这仍是作者意见。

OpenAI 官方 TTS 声名包括 `alloy` / `echo` / `fable` / `onyx` / `nova` / `shimmer`。Kokoro v1.0 有 `af_alloy`、`am_echo`、`bm_fable`、`am_onyx`、`af_nova` 等平行命名。`af_heart` 不在该名单，但同样无来源。

### 1.5 作者对 USCO 的引用过宽

实际 PDF 是 2023-03-16《Copyright Registration Guidance: Works Containing Material Generated by Artificial Intelligence》：

> If a work’s traditional elements of authorship were produced by a machine, the work lacks human authorship and the Office will not register it.
>
> When an AI technology determines the expressive elements of its output, the generated material is not the product of human authorship. As a result, that material is not protected by copyright and must be disclaimed in a registration application.

这只说明：纯 TTS 输出很难登记为使用者的版权。它不等于训练数据免 ToS，也不等于可以拿长得像微软 / OpenAI 预置声的音频做商业再分发。缺版权保护 ≠ 有权使用。

### 1.6 Edge TTS（旧片路径，不能假定商用再分发）

https://github.com/rany2/edge-tts 只描述调用 Microsoft Edge 在线 TTS，README 没有商用 / 再分发授权。那是非官方客户端。

微软对官方 Azure 自定义神经语音仍是 Limited Access，并要求披露合成声：

- https://learn.microsoft.com/en-us/azure/ai-foundry/responsible-ai/speech-service/text-to-speech/limited-access
- Enterprise AI Services Code of Conduct：对外分发需披露 synthetic nature of generated voices

不能把 Edge 消费通道产出的 `Xiaobei` / `Xiaoni` 音频假定为可公开商用再分发。即便改走付费 Azure，也是另一份合同，且仍要披露合成声。

### 1.7 对本片中文声 `zf_001` 的操作结论

- 权重：Apache 2.0，可本机推理。
- 音色：龙猫授权是作者陈述；公开片若使用，应在制作记录保留模型卡 URL 与这段原文，不要写成「已获明确商用执照」。
- 不要混用 v1.0 的 `zf_xiaobei` / `zf_xiaoni`。
- 不要用 Edge TTS 填中英轨。

## 2. 可本机运行的替代（供对照，本片已选 `zf_001`）

| 方案 | 许可证据 | 中英宣传片 |
| --- | --- | --- |
| 自己录，或签了授权的配音 | 权利在你 / 合约 | 最干净 |
| 引擎用 Apache/MIT + 只用自己的参考声。CosyVoice Apache 2.0：https://github.com/FunAudioLLM/CosyVoice ；Chatterbox MIT：https://github.com/resemble-ai/chatterbox | 代码许可明确；参考声必须是使用者拥有的 | 可行；不要克隆第三方 |
| Thorsten-Voice + Piper | CC0，明文含 commercial：https://github.com/thorstenMueller/Thorsten-Voice/blob/master/LICENSE | 德语；不解决中英片 |
| eSpeak NG | GPL-3：https://github.com/espeak-ng/espeak-ng | 可商用跑程序，音质不像宣传片 |
| MeloTTS | 库 MIT，“free for both commercial and non-commercial use”：https://github.com/myshell-ai/MeloTTS | 库可商用；预置说话人数据来源仍不如 Thorsten 清楚 |
| Piper 中文预置 | 不要当明确商用。`xiao_ya` 标 Non-commercial（DataBaker，https://www.data-baker.com/data/index/TNtts/）；`huayan` License Unknown 且从 lessac 微调；lessac 是 Blizzard 研究许可（https://www.cstr.ed.ac.uk/projects/blizzard/2013/lessac_blizzard2013/license.html）；`chaowen` 数据 CC0 但从 xiao_ya 微调 | 中文预置声不能当干净替代 |

Piper 引擎本身 MIT：https://github.com/rhasspy/piper/blob/master/LICENSE.md  
Piper voices 数据集卡 MIT：https://huggingface.co/rhasspy/piper-voices — 不覆盖每支音色的训练数据许可。
